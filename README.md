# 오픈마켓 견적서 변환기 (학교용)

지마켓·옥션·아이스크림몰(`.xls`)과 11번가(`.pdf`) 견적서를 에듀파인 업로드용 엑셀로 바꾸는 정적 웹페이지입니다.
모든 처리는 브라우저 안에서만 이뤄지고, 외부 서버나 API 키를 쓰지 않습니다.

## 내려받는 파일
| 버튼 | 시트 이름 | 열 |
|---|---|---|
| 품목내역 에듀파인 양식 내려받기 (선생님 · 품의용) | `품목내역` | 내용 · 규격 · 단위 · 수량 · 예상단가 |
| 물품내역 에듀파인 양식 내려받기 (행정실 · 원인행위용) | `물품내역` | 품명 · 규격 · 수량 · 단위 · 예상단가 · 예상금액 · 용도 |

- 금액은 견적서의 **실제 결제 금액**(할인 반영)만 씁니다. 상품 단위 할인은 옵션 금액 비율대로 나눕니다.
- 품목내역의 예상단가는 소수 셋째 자리에서 올립니다. 에듀파인이 예상금액을 `단가 × 수량`으로 다시 계산하기 때문입니다.
- 몰별 배송비는 별도 줄로 들어가고, 견적서의 총 구매금액과 맞는지 `검증` 열에 표시합니다.
- 품명은 규칙 기반으로 정리하며, 결과 표에서 직접 고칠 수 있습니다(칸에 마우스를 올리면 원본이 보입니다).
- 규격 칸에는 옵션 문구 대신 **모든 줄에 공백 한 칸**이 들어갑니다. 규격 열이 통째로 비면 에듀파인이 서식을 읽지 못해서입니다.
  값을 바꾸려면 `js/export.js`의 `SPEC_FILL`을 고치고 `node build.mjs`를 다시 실행하세요.
- 같은 상품의 옵션이 여러 줄이면 품명이 같은 줄이 여러 개 생깁니다.
- 아이스크림몰은 견적서 위쪽 「최종견적금액」 줄의 배송비·합계금액을 씁니다. 학교 예산 주문은 배송비가 0원이라 배송비 줄이 생기지 않습니다.

## 구성
- `index.html`, `style.css` — 화면
- `app.bundle.js` — 화면이 실제로 불러오는 한 파일. 아래 `js/` 소스를 `node build.mjs`로 합친 결과물이라 직접 고치지 않습니다.
  일반 스크립트라서 `index.html`을 **더블클릭해도** 열립니다.
- `js/parse.js` — 견적서 읽기 (HTML 표, 11번가 PDF)
- `js/clean.js` — 품명 규칙 정리
- `js/export.js` — 표 만들기와 엑셀 저장 (SheetJS 사용)
- `js/app.js` — 화면 동작

엑셀 저장은 SheetJS, 11번가 PDF 읽기는 pdf.js를 CDN에서 불러옵니다(인터넷 연결 필요).

## 배포 (GitHub Pages)
서버가 필요 없는 정적 페이지라 저장소를 올리고 Pages만 켜면 됩니다.
Settings → Pages → Source `Deploy from a branch` → Branch `main` / `/ (root)` → Save.
주소는 `https://<계정>.github.io/<저장소 이름>/` 입니다. `app.bundle.js`는 꼭 함께 올려야 합니다.

## 고친 뒤에는
```bash
node test/pure.test.mjs  # 순수 로직 시험
node build.mjs           # js/ 소스를 app.bundle.js 로 다시 합치기
node test/serve.mjs      # (선택) http://localhost:8123 에서 확인
```

## 확인되지 않은 부분
- 아이스크림몰만 실제 견적서 한 건으로 확인했습니다(할인이 있는 경우는 못 봤습니다). 나머지 시험용 견적서(`test/fixtures`)는
  양식 구조를 흉내 내 직접 만든 가짜입니다. **지마켓·옥션·11번가는 실제 견적서로 한 번씩 확인**하세요.
  특히 11번가 PDF는 줄을 복원하는 방식이라 양식이 조금만 달라도 결과가 다를 수 있습니다.
- 몰 이름은 문서 내용으로 추정하며, 틀리면 파일 목록의 선택 칸에서 바꿉니다.
- 만든 `.xlsx`가 에듀파인 업로드 화면에서 받아들여지는지는 실제 에듀파인에서 확인해야 합니다.
